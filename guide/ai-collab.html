本页目录

AI 辅助开发 ​

本模板将「AI 助手如何在此架构下工作」沉淀为可执行的规则与技能，存放在 .trae/ 目录，与代码同库演进。

组成 ​

内容路径职责
架构开发规则.trae/rules/architecture.md架构规范的机器强制约束层：分层调用链与禁令、插件清单（导入路径唯一事实源）、标准落码顺序、类型组织判据、UTS 红线、装配点唯一、验证 DoD
AI 行为协议.trae/rules/core-protocol.md辩证执行、工作模式（交互 / 无人值守 / 谋定而后动）、DoD 检查清单、经验教训记录
文档驱动工作流.trae/rules/workflow.md功能实现强制流程：建立任务文档 → 等待并读取回答 → 实现与验证 → 实施记录回填，全程落盘跨会话持久
通用规范沉淀.trae/rules/project_rules.mduni-app x / UTS / uvue / ucss 通用约束摘录
新功能开发技能.trae/skills/arch-feature/SKILL.md六步落码：需求确认 → DTO → api → store → 页面/组件 → 装配点检查 → 验证闭环
任务文档归档.trae/documents/按「需求类型 / 日期」两级目录归档；implementation-log.md 为全项目任务索引
MCP 配置.trae/mcp.jsonuni-app-x MCP 服务器，供 AI 查询插件与 API 平台兼容性

设计原理 ​

  • 原理层与强制层分离：仓库首页架构文档讲「为什么这样设计」，.trae/rules/architecture.md 讲「AI 必须怎么写」——二者同源、同步演进；
  • 红线不漂移：AI 生成代码时被规则约束在分层内，UTS 红线清单直接注入上下文，编译级踩坑在生成阶段就被拦住；
  • 文档驱动：需求分析、伪代码、疑问与回答全部落盘任务文档，跨会话循环推进，对话只做通知与执行。

实际收益 ​

最大的收益不是「写得快」，而是架构约定被机器执行：AI 不会为了「简洁」绕过分层，不会凭记忆写错插件导入路径，不会踩 UTS 红线清单里的坑——这些恰是人机协作中最容易失控的部分。
